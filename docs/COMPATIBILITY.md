# Compatibility decisions

## G5-A/G5-B Solidity and local EVM

`contracts/package-lock.json` pins solc 0.8.30, ethers 6.15.0 and EthereumJS
10.1.3. G5-A uses `Hardfork.Prague` and real EIP-2537 G1 MSM/pairing
precompiles to verify the existing BLS12-381 G2-B state proof. The 512-byte
EIP proof is encoded as `-A || B || C` using 64-byte big-endian Fp slots and
Fp2 `c0 || c1`; arkworks' 192-byte compressed proof is not an EVM input.
Each public scalar is checked against BLS12-381 Fr without modular reduction.

G5-B reuses the unchanged Solidity source with a new constructor-pinned P3 VK
and 60 public scalars. The 61 IC points encode exactly the two-subset G4-B
relation; selector input 51 is checked by a real changed-statement transaction.
State and disclosure keys are separate. Both gates share the same exporter
coordinate encoding and JavaScript executor while preserving their individual
fixtures, source reports and measured outputs.

The constructor pins one VK and public-input width. Gas is measured by signed
transactions in a local in-memory VM, with no RPC endpoint or public-chain
deployment. SnarkPack's pairing-target operations, complete settlement and
full batch DA remain separate gates. Sources:
[EIP-2537](https://eips.ethereum.org/EIPS/eip-2537),
[Pectra](https://eips.ethereum.org/EIPS/eip-7600), and
[EthereumJS VM](https://github.com/ethereumjs/ethereumjs-monorepo/tree/master/packages/vm).

## Native group

The native protocol uses Ristretto255 through `curve25519-dalek 4.1.3` for
weighted ElGamal, commitments, signatures, VSS/DKG and Chaum–Pedersen proofs.
Compressed 32-byte Ristretto encodings are used in transcripts.

## Groth16 P1

The P1 circuit uses arkworks `ark-groth16 0.4` over BLS12-381. It is a real
setup/prove/verify path, but only the P1 winner relation is implemented. The
upstream implementation is <https://github.com/arkworks-rs/groth16>.

## SnarkPack

G1-C0 pins the crates.io release `bellperson =0.27.0` and invokes its real
SnarkPack `AggregateVersion::V2` path on BLS12-381. The source G1-B2 proofs and
verification key are generated by `ark-groth16 0.4.0`; canonical BLS12-381
points and scalars are converted to `blstrs 0.7.0`, then individually verified
by bellperson before aggregation. The minimum supported power-of-two batch is
two proofs, and all 25 public inputs per proof are encoded into the external
aggregation transcript.

The measured G1-C0 run uses bellperson's deterministic `setup_fake_srs` helper
only to test functional compatibility. It is not a production aggregation
ceremony or an efficiency claim: the 5,236-byte aggregate proof is larger than
the two 192-byte source proofs at this minimum batch. Scale experiments and a
production aggregation SRS remain separate gates. Sources:
<https://eprint.iacr.org/2021/529.pdf> and
<https://github.com/filecoin-project/bellperson>.

## Hash to scalar

Transcript challenges use SHA-512 with explicit domains and a bounded rejection
loop. A candidate is masked to 253 bits and accepted only when it is a canonical
Ristretto scalar; the accepted counter is serialized with the proof. The
protocol limit is exactly 128 attempts and failure is returned, never replaced
with modular reduction.
