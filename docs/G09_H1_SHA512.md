# G0.9-H1 SHA-512 circuit feasibility

Status: `PASS_H1_SHA512_R1CS_EXACT_DIGEST`.

H1 evaluates one real SHA-512 R1CS over the exact 684-byte generalized-CP
transcript frozen by H0. It is an isolated hash-circuit measurement, not a CP
proof circuit or P3.

## Implemented relation

The circuit:

1. allocates the 684 transcript bytes as witnesses;
2. applies standard SHA-512 padding, producing six 128-byte blocks;
3. evaluates all SHA-512 compression rounds in R1CS;
4. packs the expected 64-byte digest into three public field elements; and
5. constrains every computed digest byte to the public digest.

The expected digest is:

```text
8534949b00278a5d89b755ad9855def34cd69b695c86c67aa15079e2c8d842aa
93b00855a9a854401d40bc79c2faa885980045a361d89eb10228515830b18d5f
```

It exactly matches the native SHA-512 value stored in
`fixtures/jubjub_cp_transcript_v3.json`.

## Reproduce

```bash
cargo +1.99.1 run -j 2 --release --locked -p vv-friendly-crypto \
  --bin friendly-cp-transcript-h1
```

The current repository requires Rust `1.99.1`; the host's default `stable`
toolchain is not used for this measurement.

## Claim boundary and next gate

H1 hashes the frozen CP transcript directly. It does not yet constrain the
Suite v2 hash-to-scalar domain wrapper, 252-bit masking or rejection counter.
It also does not integrate CP group equations, package commitments, threshold
reconstruction, the winner relation or Groth16.

The next single necessary experiment is G0.9-H2: constrain the exact native
hash-to-scalar wrapper and bounded rejection rule, then compare the resulting
scalar and counter with the frozen vector. CP integration remains outside H2.
